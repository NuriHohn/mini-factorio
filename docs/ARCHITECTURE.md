# Implemented architecture

This describes the current source, including offline persistence and categorized build tools. Gameplay values and selection policies are maintained in [Game design](GAME_DESIGN.md); proposed systems belong in [Roadmap](ROADMAP.md).

## Ownership and source map

TypeScript spans all layers. Simulation modules have no React, Phaser, Zustand or DOM dependency. Functions mutate an explicitly supplied `World`; `FactoryScene` owns the live instance. React never owns a second simulation or receives mutable inventories. Phaser owns rendering/input; Zustand carries commands and copied summaries. Gameplay timers and decisions use simulation state, never wall-clock timers or rendering callbacks.

## State and exact update order

`World` holds nature decorations/global Wood/RNG, research currency/unlocks, ore-ID-or-null resource terrain, a separate boolean water mask, tile-indexed physical occupancy (buildings and trees, `y * SIZE + x`), per-item lifetime `mined`/`produced` inventories, elapsed remainder, topology revision and derived power state. Buildings contain buffers, belt progress/entry direction, machine jobs and selection state, plus inserter phase, elapsed swing time and held item. Terrain generation accepts an RNG; equal initial state and equal inputs/time progression must produce equivalent outcomes.

`advanceWorld` rejects nonpositive/nonfinite deltas, retains elapsed remainder and runs complete **50 ms** steps in this order:

1. `createInserterFrame`: capture relevant old source quantities and initially occupied destination belts.
2. `advanceTransport`: advance existing belt items and commit reserved transfers.
3. `outputMachines`: export buffered miner/furnace/assembler items; exclude belts just vacated by belt transport.
4. `allocatePower`: refresh topology if invalidated, then calculate current demand and proportional supply. `advancePolice` then uses this current allocation for detection, advances one police operation or releases/escapes a prisoner. `advanceSprinklers` then uses the same current allocation; a dispatched/committed police case blocks new spraying.
5. `advanceInserters`: atomically pick up/deliver in inserter tile order using allocated power and the step-start budget.
6. `observeMachines`: observe readiness/allocation for this interval without changing gameplay. `advanceCrafting` progresses/completes existing jobs, credits actual research processing time, and starts eligible jobs without changing locked recipes.
7. Mining: advance unblocked miners by allocated power fraction; buffer completed ore and update `mined`, crediting research only for actual powered progress. Production hooks record actual quantities; analytics pruning expires old rolling samples/history.

Each fixed step first advances `World.timeMs` by 50 ms, runs due-only `advanceNature`, expires/lands/checks webs with `advanceWebs`, then runs `advancePete`. Projectile impacts set a building-owned absolute `sabotageUntilMs`; power allocation sees that state in the same boundary. `sabotageRemaining` is the shared read-only timer query for allocation, inspection and visuals. Suppressing working demand reuses existing zero-speed production pause behavior without modifying jobs or duplicating crafting logic. Normal transport/export remains unchanged.

New crafting jobs begin with zero elapsed time; finished products export on a later step. An assembler completing a job keeps its locked recipe and may start the next batch at that boundary. Readiness newly supplied by an inserter receives processing power on a subsequent allocation; new jobs still start at zero. Phaser also calls `allocatePower` after stepping for current visual/inspection data; that call does not advance simulation time.

## Crafting and inventories

Recipes contain quantity maps rather than one hardcoded ingredient/product. Furnace and assembler selection policies feed the same `canStartCrafting`/`advanceCrafting` core. Manual changes pass `recipeChangeError` and compatibility checks; UI disabling alone is insufficient.

Job creation atomically checks complete ingredients and output space, subtracts ingredients, and stores `ProcessingJob.inputs`, `outputs`, `recipeId` and `elapsedMs`. Committed inputs leave the input buffer but remain accountable in the job. Job outputs reserve capacity; they are not physical products yet. Completion atomically adds all outputs, increments `World.produced` by their actual quantities, and clears the job once. Missing input or insufficient output space prevents a new job. Zero power preserves jobs and prevents starting; fractional supply scales elapsed processing by machine crafting speed.

Furnace `incomingRecipe` is a read-only probe; transport reserves its chosen recipe across simultaneous deliveries. `assemblerRecipes.ts` provides capacities for explicitly selected recipes; it never selects recipes. Both feed shared crafting through simulation-owned `recipeLocked`, job and buffer state; selection must not move into rendering or a second crafting engine. The authoritative Auto/Manual policies, retained pre-lock stock and switching restrictions are in [Game design](GAME_DESIGN.md#automatic-and-manual-recipes).

## Transport and electricity

Transport first plans against unchanged occupancy, reserving capacity per destination and item, then commits accepted transfers. Furnace recipe reservations prevent mixed simultaneous arrivals selecting different recipes. Source tile order resolves competing inputs. New arrivals do not travel twice in the same step. Machine outputs target only front belts and choose the first available product in item registry order, one unit per machine per step. Rejections retain the source item. Visual input priority is separate from transport arbitration.

Inserters reuse `canReceive`/`deliverItem` from transport for ports, input limits, belt occupancy and furnace recipe detection. They extract finished output only, select chest items in item registry order among currently acceptable candidates, and remove a physical unit into their own held-item field. Carrying does not reserve future destination capacity: delivery is revalidated, so blocking, removal or recipe changes retain the item safely. The half-second outward and return phases advance with allocated power. Reaching a blocked drop point stops demand until delivery becomes possible.

The ephemeral `InserterFrame` bounds pickups by old source quantities even if belts or earlier inserters add replacement units. Initially occupied destination belts remain unavailable to inserter delivery for that step. Existing belt transfers and automatic machine belt output run first; inserter claims then commit sequentially in stable tile order against current quantities and capacities. This prevents overbooking and passing new arrivals through two transfers in one step. The frame is not stored in world or UI state.

Power topology is cached against `topologyRevision`; successful placement/removal increments it. Pole edges join connected components. Machines/generators use their lowest-index covering pole, giving one deterministic network assignment. Coverage overlap alone never joins networks. `allocatePower` recomputes working demand each call and supplies each requesting consumer at `min(1, network capacity / network demand)`. Uncovered consumers receive zero. `powerOverview` keeps network surpluses separate from deficits. `polePlacementPreview` uses the same connectivity functions without mutating topology.

## Commands, rendering and lifecycle

Toolbar clicks and non-repeating placement/deletion hotkeys use the same atomic `select` toggle action; Escape consumes only the most immediate pending drag, panel or tool interaction. `tool` is the only placement/removal authority: React derives `aria-pressed` and styling from it, while Phaser reads it for previews and click behavior. Inspection is admitted only when the active tool is null. Player-facing toggling, Escape, focus and category rules are in [Game design](GAME_DESIGN.md#world-items-and-controls). A scene-managed DOM key listener delivers Escape even with form focus and is removed on scene shutdown; other tool keys ignore form editing.

React sends a recipe intent through Zustand; `FactoryScene.update` revalidates it against the live building before stepping. `inspectBuilding`, `electricalDetails` and `worldStats` derive copied summaries. Store publication compares values and avoids unchanged updates; item positions stay outside Zustand.

Phaser draws terrain, machines, wires, coverage, items and placement previews procedurally. Furnace glow and assembler gear angles derive from actual job elapsed time, so processing animation pauses without power. Inserter arms and held-item positions follow their actual powered phase elapsed time, using a pure tile-local swing path. Straight/curved item paths use the actual belt entry; topology connections remain visible when empty. Pole preview links are cached by hovered tile and topology revision in world coordinates, so camera transforms do not require connectivity recalculation. React's canvas effect disconnects its observer and destroys Phaser on cleanup, including Strict Mode remounts.

## Frame pacing and rendering efficiency

`GameCanvas` installs one `FramePacer` gate around Phaser's complete `game.step` callback in `postBoot`. Phaser still owns requestAnimationFrame, input, update and rendering; skipped callbacks perform none of the scene or renderer work. There is no second interval, busy wait or concurrent simulation loop. The previous configuration had no FPS limit (Phaser's target alone does not cap foreground rendering). The built-in limiter clears its accumulated delta after each admitted callback; the explicit gate instead retains fractional deadline phase, skips missed deadlines, and passes actual admitted-frame elapsed time. Phaser delta smoothing is disabled so frame pacing cannot change the amount of simulation time supplied.

Graphics limits and player-facing suspension/stall policy belong in [Graphics options](GAME_DESIGN.md#graphics-options). The deterministic `advanceWorld` engine and 50 ms steps are unchanged. The scene continues to handle commands before stepping, and autosave receives only actual advanced simulation time. Visibility changes reset pacing and diagnostic windows; hidden callbacks return before Phaser update/render. Blur alone still cancels gestures without pausing a visible factory. Existing transactional load delta suppression remains in place.

`TerrainVisuals` rasterizes terrain/ore/banks into twenty-five retained 8×8-tile Canvas textures (256×256 pixels each, approximately 6.25 MiB total uncompressed RGBA). Phaser camera-culls their images; unchanged frames do not replay tile Graphics commands. During landscaping, only chunks intersecting changed cells and their one-tile diagonal shoreline halo redraw, once in the next admitted frame even if several pointer events changed them. Repainted/rejected cells do not invalidate anything. Building/removal/nature actions affect their own layers without touching terrain textures. A complete replacement cache is prepared hidden before transactional world replacement; failure destroys only the candidate, success destroys the old images/textures. Shutdown/destroy releases the current cache. Rendering cache data never becomes a second authoritative water mask.

`viewport.ts` derives current camera bounds directly from scroll/zoom, before Phaser's `preRender` updates `worldView`. Building/item/tree iteration covers visible tiles plus a two-tile safety margin. Wires use intersection bounds (not endpoint visibility); coverage includes its full radius. Decoration Graphics cache keys include visible tile bounds, decoration/topology revisions and world identity. Water retains its existing site cache and viewport checks. Optional viewport arguments suppress offscreen NPC/effect geometry with conservative effect-specific margins; web fades, puddles and impact expiration still run when offscreen. Very small, bounded home poses remain inexpensive. Text retains Phaser camera clipping. No culling decision affects simulation or authoritative occupancy.

Regular copied HUD/analytics/inspection publication is limited to once per 100 simulation milliseconds; world replacement and topology changes publish immediately, and existing direct inspection/research commands retain their updates. This avoids constructing summaries on every render and on frames with no simulation step. Analytics collection remains inside each fixed step. `graphicsSettings.ts` owns the separate best-effort `mini-factorio.graphics-mode` localStorage preference; it never changes the save format or world state. Optional diagnostics use a separate store with at-most-once-per-second publication, measuring admitted frames, synchronous update/render-submission work and the last simulation batch's amortized tick cost. They do not measure GPU execution time or count draw calls; displayed object counts cover drawn buildings only. Disabled diagnostics avoid performance-clock sampling.

## Invariants and extension points

Preserve nonnegative integer quantities, complete atomic batches, output inventory plus reservations within capacity, and stable transfer/selection priorities. Count active job inputs and held inserter items in material conservation, never promised outputs. A gear represents two iron units; a cable half a copper unit; a circuit one iron plus 1.5 copper units. Deliberate building removal is the discard exception and preserves lifetime counters. Chest totals are stored inventory, not total world inventory.

Preserve existing item/recipe/building IDs and reuse the item/recipe/machine registries, shared crafting, transport, power and inspection systems. Placement, capacity and recipe/mode changes must be validated by simulation APIs, not only UI checks. Extend the existing metadata and shared core before adding special cases. Keep future machine ports/capacity policies in simulation data, invalidate topology through supported operations, and extend snapshot/UI presentation without exposing live state. Do not introduce a second crafting engine or renderer-dependent planning rules. Preserve unique furnace Auto detection and explicit assembler selection with their regression suites.

## NPC state and rendering lifetime

`World.pete` holds a normal, web-reaction, police-custody or water-reaction state, tile-to-tile interpolation, a seeded 32-bit LCG, escape path, cooldown, crying/web clocks and at most one in-flight pumpkin. Pete and police share stable cardinal neighbor order and breadth-first path queries; breadth-first search only runs for a new escape route or topology change. For web fleeing, a reachable destination minimizes distance to any corner, then tile index. Wandering tests empty adjacent tiles; construction reserves Pete's current/next tile, and cached pole previews include these reservations in their key.

Projectile snapshots retain the target building identity as well as its tile index: deletion/replacement cannot redirect a hit. The target reference is serializable with `structuredClone`, and no unbounded event history is retained. Elapsed sabotage timestamps on removed buildings have no world effect. Existing fixed-step remainders make behavior independent of frame partitions.

Phaser converts clicks to world coordinates and delegates to `useWebTool` only when `spiderWeb` is selected. Ordinary clicks follow the existing building/inspection path. A consumed web click cannot place/delete a building. Direct hits use the shared forgiving hit query and do not wait for a second collision; protected water/custody hits are consumed without a scare. The [gameplay click/state rules](GAME_DESIGN.md#pete) determine eligibility. Movement carries unused fixed-step time across tile boundaries and uses shared walking/fleeing constants. Zustand only dispatches this command and copied inspection data; NPC positions/inventories remain authoritative in the scene's world. Camera conversion is shared with building clicks.

A single reused graphics layer redraws Pete, the bounded projectile/web effect and currently sabotaged buildings. Splatter reads building position and authoritative remaining time on every frame; no particle objects or independent expiry timers are allocated. It disappears on expiry or deletion, with a building-identity check guarding stale references. Bubbles, tears and walking bobs derive from simulation time, so rendering cannot extend a disable duration. One reused text object labels Pete.

## Police custody invariants

`World.police` owns at most one car/case, a bounded radar-flash snapshot, retry time, and a topology-revision cache of radar indices. Empty factories do not run a tile scan per step. Radar demand and full-allocation detection use the shared simulation power/range queries, never a Phaser approximation; values are in [Game design](GAME_DESIGN.md#police-radar-traps-and-prison). Dispatch is arbitrated by radar tile order after allocation. Prison creation uses supported placement and invalidates topology; it never overwrites a building or consumes the only reachable edge entry.

The car holds its continuous position, current/next tile, bounded route, route revision/target, `RESPONDING`/`ARRESTING`/`TRANSPORTING` phase, arrest elapsed time and the prison building identity. Routes replan at tile boundaries when the target or topology changes. Construction reserves car current/next tiles and prison exits. Obstructed/unreachable return routes abort safely with the passenger released, not moved through a wall.

Pete adds `ARRESTED`, `TRANSPORTED`, `IMPRISONED`, a prison identity, imprisonment start boundary, sprinkler grace deadline and bounded jailbreak snapshot. His cooldown still advances in `advancePete`, but custody stops independent movement and sabotage. Arrest cancels in-flight pumpkin state. Prison arrival records `imprisonedAtMs`; escape compares elapsed simulation time against the shared imprisonment duration. Release/escape sets the sprinkler grace deadline without touching sabotage cooldown, clears custody references and stale police retry deadlines. Police dispatch ignores sprinkler grace (including deadlines in existing saves) and polls current radar coverage; automatic release checks dispatch on the same fixed-step boundary. Gameplay durations belong to [police/prison rules](GAME_DESIGN.md#police-radar-traps-and-prison).

The prison inspector receives copied elapsed/remaining times, occupancy and an imprisonment timestamp token. Zustand queues `{index, imprisonedAtMs}` release intent; the scene applies it through `releasePete` before stepping. Validation checks current mode, building identity and timestamp, so duplicate/stale commands cannot release another case. Switching tools/inspection cancels pending release intent. Imprisoned Pete yields pointer priority to his prison; during arrest/transport his clicks remain consumed. Removal is handled synchronously through the supported building-removal hook, which frees a captive or cancels an arrival before the prison disappears.

Graphics reuse the existing effects layer and simulation snapshots; flashing lights, angry eyebrows, shaking bars and dust have no gameplay authority or independent timers. An empty prison remains inspectable. Removing it immediately removes bars; jailbreak dust is bounded and naturally expires. Police/prisons have no item inventories and do not participate in transport or recipes.

## Compact splitter extension

`Splitter` is one logical 1×1 building in the existing flat building array. It adds a direction, optional intake packet, two optional outgoing packets (front/left), next-output preference, per-output delivered counts and placement time. Packets hold an item type and stage progress; capacity is bounded at three total. No multi-tile occupancy structure or second transport engine is introduced.

`advanceTransport` orders sources by tile, then front/left output slot. It ages only existing belts/packets, reserves all external belt/splitter deliveries against unchanged occupancy and shared machine recipe/capacity maps, then plans intake-to-output routes against unchanged slots. External deliveries commit before internal routes, but all plans predate either commit. New arrivals cannot be routed, just-vacated output slots cannot be reused, and new outgoing packets start at zero progress. A route changes the round-robin preference only when committed; in-flight destination capacity is rechecked on actual delivery rather than reserved for 250 ms. Stuck output packets never block the other outgoing slot.

Shared `canReceive`/`deliverItem` enforce rear-only splitter input and one intake reservation. `createInserterFrame` budgets physical outgoing packets; extraction rechecks the correct front/left slot, readiness, direction and budget, then counts the departure once. Existing buffers, recipes, actor occupancy, topology invalidation and machine exports keep their existing rules.

`splitterDirections`/`splitterPorts` are the shared geometry authority for preview, transport, belt connections, inspection and inserters. Pure game path functions join rear edge → center → selected edge continuously and align with neighboring belt entry. Phaser draws static branching lanes and interpolates only simulation packet progress; no routing decisions occur in rendering. Inspector packets/arrays are value copies. Delivered average is cumulative departures divided by simulation time since placement, not an instantaneous throughput estimate.

## Versioned offline persistence

`src/persistence/saveGame.ts` owns `SAVE_FORMAT` and `SAVE_VERSION` (currently 37), JSON snapshots and detached reconstruction. `validation.ts` validates every required field, rejects unknown fields/IDs, checks finite bounded numbers, complete inventories, ports, buffer limits, recipe/job reservations, actor movement and cross-object references. No Phaser or React imports are needed. JSON is limited to 2 MiB. Versions 1 and 2 are explicitly accepted with their original strict field sets: version 1 lacks water state, and both lack ground-web/trap fields. They reconstruct empty webs and null trap state. Legacy tile travel elapsed time is divided by the walking-speed increase factor, preserving the serialized position/fraction while applying the new speed; remaining cooldown, crying, water and custody timers are retained. Legacy files cannot contain new fields or expanded sabotage targets. Version 3 retains its strict Pete/web schema. Versions 1–3 initialize empty analytics at the saved clock; existing assembler locks/jobs/stock survive, while provisional candidates are cleared and legacy waiting timers stop. Version 4 preserves its strict analytics schema. Versions 1–4 migrate to zero RP and all Sprint 11 technologies unlocked. Version 5 requires explicit validated research state; subsequent saves write version 37. Version 5 retains its exact RP/unlocks; versions 1–5 initialize an idle Revenge event with threshold 3 and count 0, and newly introduced Revenge Defense IDs remain locked. Unknown versions are rejected clearly; there is no best-effort partial loading.

The document contains `{ format, version, savedAt, map, game, view }`. `savedAt` is ISO UTC wall-clock metadata only. `map` records the supported dimensions. `game` contains tiles, tile-indexed buildings, counters, time/remainder, topology revision, Pete's RNG/movement/effects/timers, web flights/patches/identity sequence, police/prison authoritative state, bounded analytics observation state, research currency/unlocks, and Revenge encounter/combat timers. Building fields retain all item packets, elapsed progress, recipe modes/locks, committed jobs/reserved outputs, inventories and splitter round robin/counters. Object references (prison and pumpkin target) become validated building indices, then are linked to candidate building objects on decode. A projectile whose target was already deleted is omitted, matching its next-step cancellation; no resource or timer is discarded.

Power allocations/networks and police radar caches are derived and excluded. Decoder rebuilds power from buildings and invalidates the radar cache. Path/topology revisions remain serialized because they affect deterministic navigation decisions; cached future paths may be stale after placement and are revalidated by normal movement logic. Phaser graphics, input listeners, React state, active tools, inspection commands, DOM objects and file handles are never serialized. `view` restores camera scroll/zoom, output direction and power overlay; tool/inspection reset is intentional.

`SaveSession` in `storage.ts` owns two localStorage keys: `mini-factorio.manual-save` and `mini-factorio.autosave`. It uses consistent synchronous snapshots, prevents reentrant saves, tracks last-success timestamps and accumulates active gameplay against `AUTOSAVE_INTERVAL_MS`. The save controls/cadence are documented in [Game design](GAME_DESIGN.md#offline-save-and-load). Autosave never writes the manual slot. Storage exceptions do not erase old data. `download.ts` creates a local JSON download, with no network service or extra dependency. Persistence uses no backend, accounts, tokens, IndexedDB or named-slot manager.

React `SaveControls` sends commands through Zustand. `FactoryScene` validates/reconstructs first, confirms replacement, stages terrain graphics while hidden and commits the candidate into the existing scene. Failure restores the old world/view/store; old terrain is destroyed only after success. Loading never restarts the scene or registers more listeners/loops. Confirmation-frame deltas are discarded so time spent in the browser dialog is not replayed into the simulation. Load/import/export do not write a browser slot. Startup only reads metadata; loading is explicit.

## Sprinkler and water reaction ownership

`Sprinkler` adds only `cooldownUntilMs` and completed `sprays` to the one-tile building union. `sprinklers.ts` reuses shared power, Euclidean range, cardinal neighbors and breadth-first paths. It adds no inventory, transport branch, recipe or independent NPC loop. Placement/removal still invalidates topology normally. Demand and readiness/jet checks reuse `SPRINKLER_KW` and current allocation; [Game design](GAME_DESIGN.md#anti-goblin-sprinkler) owns the values and power-interruption behavior.

`Pete.water` is null outside `SPRAYED`/`SLIPPING`/`COMPLAINING`/`WATER_FLEEING`. During a reaction it holds the source position snapshot, an active source index only while spraying, remaining phase milliseconds and deterministic complaint index. Existing Pete tile/next/progress/path/revision/escape fields carry navigation. Stationary phases preserve sub-tile position and reserve existing current/next tiles; entering/leaving water fleeing rescales interpolation to/from ordinary movement speed without teleporting. The reachable escape destination maximizes squared distance from the source, ties by tile index, with topology-based replanning. Reaching the destination/enclosure does not shorten the reaction or trigger crying.

`advancePete` always advances shared sabotage/web/jailbreak clocks first. Water slip/complaint/flee phases advance there and return before ordinary wandering/sabotage. Spraying waits until `advanceSprinklers` after current power allocation and police processing; its first boundary initializes the shared spray duration without aging immediately. Completion initializes slipping and the source cooldown once. Later reaction phases use their shared unscaled simulation-time constants; durations are in the [reaction table](GAME_DESIGN.md#anti-goblin-sprinkler). Step-start water state suppresses new sprinkler activation on the same boundary that its reaction ends; this ephemeral guard is reconstructed naturally from saved state. Police dispatch wins simultaneous eligibility; existing approach/custody and post-release grace block activation. Water reactions block new dispatch, not committed cases. Interrupting the projectile discards only its not-yet-landed action and never changes already-disabled machines or sabotage cooldown.

Current persistence validates the phase/mode pair, 50 ms bounded phase time, source type/position, complaint index, cooldown, navigation and absence of conflicting custody/projectile/grace state. Source deletion synchronously starts slipping and clears its index; later navigation uses a position snapshot rather than a removed building reference. Version-1 upgrade is explicit and tested; slots are not overwritten by migration/loading. Detached reconstruction and transactional scene restoration remain unchanged. No rendering entities are saved.

`WaterVisuals` samples rendered flee positions at most every 400 simulation ms into a maximum of 14 puddles, expiring after 5 seconds. This cosmetic history resets on world replacement and never affects movement, resources, placement or power. Immediate-mode jets/droplets/slip splashes and wet-goblin poses have bounded draw counts. The existing single Pete text label becomes the complaint bubble text, so loads and repeated reactions do not add labels/listeners/emitters.

## Research authority and exact accounting

`World.research` owns `balanceUnits` (a canonical nonnegative decimal integer string) and unlocked stable IDs from `TECHNOLOGIES`. `RP_UNITS = 60,000,000,000` represents one RP. Mining and crafting use `awardResearch` at the actual progress mutation: subtract rounded cumulative nanosecond boundaries, multiply by the building's integer RP/min rate, and accumulate with BigInt before serializing to a string. Boundary subtraction carries sub-nanosecond progress across fixed steps; completing a job totals its exact duration regardless of partial-power step rounding. Crafting caps at the recipe duration and gives newly committed jobs no elapsed credit. Miners retain existing fractional carry across completed ore. The simulation clock/50 ms allocation defines production; rendering/publication, analytics queries and wall-clock timers never generate RP. Currency survives machine removal. The display rate reads current allocated speed and active jobs/deposits, independently of item throughput and analytics utilization.

`purchaseTechnology` validates known IDs, permanent unlock status, prerequisites and full integer balance before either deduction or unlock. UI purchase intents are drained once by the scene against its live world; stale/duplicate purchases cannot charge twice. `placementError` enforces the building-to-technology map for every authoritative placement path; existing buildings never stop functioning because of research. Store selection/hotkeys additionally reject locked tools with feedback. Dashboard toggle/focus commands and rendering require Analytics I; underlying analytics updates are untouched. Zustand publishes detached research copies, closes unauthorized analytics after world changes, and world replacement clears pending research intents and transient panel/feedback state. The native modal dialog contains focus; Escape closes it without also cancelling the underlying tool. Its confirmation timer is cosmetic only.

Research validation, introduced in version 5, requires both fields and rejects unknown fields, malformed/noncanonical/negative/oversized integer balances (maximum 40 digits), missing Basic Industry, duplicate/unknown technology IDs and missing prerequisites. It does not reject existing buildings merely because their technology is locked: they remain functional. Older schemas reject hidden research fields and explicitly migrate all Sprint 11 technologies at zero RP; ordinary new-format loads never default away progress. The exact integer balance and in-progress machine boundaries together guarantee save/load continuation without a second research-progress cache.


## Revenge event and combat authority

`World.revenge` stores one explicit event stage (`idle`, `warning`, `hunting`, `stomp`, `defeating`, `stunned`), arrest progress/odd threshold, stage deadline, optional walker, shared player cooldown/duration and independent shared police/sprinkler timers. The arrest hook runs only on `ARRESTING → TRANSPORTING` completion, after clamping the escort timer. Only idle stages accept progress. `damageWalker` is the single player/police/sprinkler damage entry point, checks liveness, and commits either the first surviving phase transition or defeat once. Defeat clears the car, resets progress and raises threshold immediately; subsequent damage is rejected. Breakdown completes through a free-tile ejection and a five-second recovery deadline, without touching building buffers or jobs.

Each fixed step reads the normal current power allocation, then `advanceRevenge` advances the warning/movement/EMP/stomp/recovery state. A new EMP/stomp updates existing sabotage fields and refreshes allocation before police, sprinklers, crafting, mining and RP accounting; disabled production cannot receive one extra productive interval. Other steps reuse the existing allocation. Target readiness reads authoritative power/jobs/deposits, not rendered analytics. Tile-ordered spawn prefers an edge component that can approach a productive machine (each component is visited once), then an operational generator-only component before falling back to the original first free edge. Acquisition prioritizes productive machines above generators; selected targets remain stable through brief readiness changes. Generator readiness reuses `ratedGeneration`/`generationKw`, including sabotage and waterwheel facing-water checks; it does not read consumer allocation or require a production job. Conventional generators and waterwheels share the last priority, with the same previous-target/distance/tile tie breaks. A fixed-step `targetInactiveMs` counter resets on productive work or operational generation; five continuous inactive seconds, removal, or unreachable approach at a tile boundary triggers reacquisition. Cardinal BFS approach routes preserve determinism; movement interpolates current/next tile over 750 ms and construction reserves both. With no reachable productive machine or operational generator, the walker reuses cardinal-neighbor navigation and a fixed tick/tile integer hash for wandering, with no new RNG state. Target checks continue every step, even mid-traversal; turns wait for the next tile boundary. Water/building changes cancel blocked traversals safely. Enclosed walkers retry when a route opens.

EMP cooldowns are 4,000/3,000 ms by phase, including the initial phase-1 deadline and the post-stomp phase-2 reset. `empTargetEligible` requires productive work or operational generation and checks the entire radius-3 splash area against existing `sabotageUntilMs` plus a 2,000-ms recovery window. This prevents repeated/overlapping EMPs extending outages indefinitely without adding per-building state. EMP/stomp durations, radii and damage remain unchanged; stomp still preserves longer disable timers. Rendering reads the same EMP eligibility, clamps charge presentation and draws a separately culled selected-machine outline without gameplay writes.

Existing Pete/web/police/sprinkler modules consult `peteUnavailable` during piloting/defeat/stun. At spawn, Pete is reset onto the free edge with no competing custody, water, projectile or trap references. The normal police dispatch/car/path system targets the boss during hunting/stomp and deals globally rate-limited close-range damage instead of starting an arrest. Sprinklers reuse full-power, range and per-building cooldown checks, plus a shared boss timer. Outside these event stages the original paths continue unchanged. The actor remains a valid frozen Pete for persistence, while the cockpit renderer hides his ordinary sprite. This avoids adding a second NPC or duplicating arrest mechanics.

The tool registry adds three mouse-only tools without changing any existing hotkey. Selection checks research, and `attackWalker` rechecks actual world unlocks and one shared simulation deadline. `combatPosition` uses the live Phaser camera’s unprojection (with a pure default-transform fallback for tests). Accepted hit/miss results contain copied world coordinates for the renderer; cooldown-rejected clicks emit nothing. Placement previews exclude combat tools, and input returns immediately after combat handling. Renderer-owned impact arrays/text are bounded, expire on simulation time, clear on world replacement and destroy on shutdown. Cockpit movement, raised foot, electrical/dust rings, wobble, smoke, ejection and local hit reactions never write gameplay or call RNG. The persisted most recent blast is observational presentation; its damage is already committed and never replayed by rendering/loading.

Version 6 requires explicit Revenge state; legacy strict schemas reject hidden new fields or new research IDs. Validation checks exact keys, odd thresholds, legal progress/stage/boss combinations, HP/phase/one-time stomp consistency, neighboring unoccupied movement and interpolated position, bounded fixed-step deadlines, cooldown duration, target bounds, blast bounds and independent-Pete/custody conflicts. Version-5 research is validated against the five historical IDs, so a newly added technology is never silently granted. Round-trip/continuation tests cover warning, moving/EMP, phase 1, telegraph, phase 2, breakdown and stun. The optional `boss.targetInactiveMs` extension preserves save-version-11 compatibility: absent metadata identifies legacy 1,500-ms traversals, validates their original coordinates and converts elapsed travel proportionally to 750 ms with zero target inactivity. Converted progress can lie on 25-ms boundaries; movement still advances only on the 50-ms simulation tick, without rounding the saved position. New metadata is strictly bounded to 0–5,000 ms on 50-ms boundaries, and must be zero without a target. Wandering needs no separate persisted state.

Decoration graphics rebuild only on decoration revision, topology change or world replacement; variation hashes tile indices and does not depend on the evolving RNG. Chopping effects are renderer-owned, capped at 32, expire on simulation time, hide under new occupancy and clear when a world is replaced. No cosmetic stumps or gesture history are serialized.

The writer omits derived decoration revision and earliest-deadline caches; the decoder rebuilds them without advancing time/RNG. Versions **1–6** keep their old schemas and reconstruct empty nature, preserving their previous gameplay migrations. ## Atomic construction gestures and beginner diagnostics

`simulation/construction.ts` owns read-only `planConstruction`/`placementInfo` and the authoritative `commitConstruction` command. `simulation/beltConstruction.ts` owns belt action classification, direct gesture intent, conservative receiver selection and packet-safe redirection. A single land-cell click validates the occupied belt using its current axis, then commits the selected direction in place; drag proposals retain axis restrictions. `placementError` accepts an optional belt direction for axis-aware construction validation after normal research/actor checks; raw `placeBuilding` deliberately omits it and still refuses to recreate an occupied belt. `ConstructionCell.reuse` excludes both reused and reversed belts from new construction, while `reverse` distinguishes actual direction changes. `beltSnap` marks an external receiver without adding or modifying it.

Belts prefer a valid direct L proposal. Otherwise `simulation/beltRouting.ts` searches cardinal incoming-direction states, checking each candidate outgoing direction through the same validator. Existing cells require aligned incoming/outgoing flow. Geometry results are cached per site/output and search passability per site/incoming/output. Only the original direct proposal grants permission to reverse a belt at that tile/output; incidental existing belts must retain their actual output. Integer costs prioritize shortest paths, then fewer new tiles, then turns; Manhattan distance is an admissible lower bound. Stable heap insertion/selected-direction neighbor order resolves ties. Parent chains reject repeated tiles before enqueueing. Search remains within the endpoint rectangle plus eight cells, capped at 4,096 expansions; it never runs in the simulation step. New endpoint turns require a unique external rear-compatible receiver matching the selected facing; existing endpoints and single clicks are never auto-rotated. Search/action/snap metadata is ephemeral and does not enter save state.

`simulation/powerRouting.ts` owns a bounded Dijkstra search over valid/reusable pole sites, with electrical edges generated through the existing `polesConnect` and `POLE_CONNECTION_RANGE` (not cardinal walkability or line of sight). Eligibility is memoized per site per search using `placementError`; existing poles remain unchanged reusable vertices. Integer lexicographic costs minimize new poles, then total ceil-Euclidean millitile wire length, then links. Each priority tier outweighs every possible lower-tier simple path within the finite grid; stable row-major neighbor generation/insertion resolves ties. The rectangle spanning the endpoints plus eight cells is map-clipped; the search stops after 1,600 expansions. Exhaustion and no local route return distinct failures without mutation. `routingQueue.ts` contains the same stable binary min-heap extracted from the belt planner and shared by both searches; the queue ordering and power routing rules are independent of belt action policy.

Power endpoints use exact start/existing-destination sites. A valid empty dragged destination also offers existing cardinal-neighbor poles as explicit alternative goals, evaluated with the same cost ordering; single-click placement has no alternative goals. Invalid endpoints are rejected before snapping/search. `ConstructionPlan.snapFrom` is preview metadata only: reused sites carry `reuse`, requested snap tiles are marked separately, and the scene counts only new sites. Commit reruns the whole planner (including snap decisions) against live state. No second power-network implementation or simulation timer is introduced.

Commit recomputes the plan against the current world and validates the entire proposal before invoking `placeBuilding` for unique non-reused cells. JavaScript does not yield between validation and these commits. A defensive unexpected placement failure rolls back only the newly created belt/pole cells and the topology revision; no existing belt or packet has been modified at that point. Once all new placements succeed, the prevalidated direction changes update existing objects in place and invalidate topology once. For 180° reversals, straight carried packets mirror progress and swap entry for continuous position; side-entered packets retain entry/progress. Single-click 90° turns retain progress and change entry only when it would equal the new output, maintaining the persisted `entry !== direction` invariant. Item quantity/identity, actors, RNG, analytics and currency are unchanged. Ordinary land belts and poles remain free; bridge Wood is charged once as described under [Water terrain](#water-terrain-and-bridge-ownership). `placementInfo` separates treehouse geometry from funding by querying a detached shallow candidate with sufficient Wood; live stock is never changed by preview validation. All implemented footprints are one cell and use the existing occupancy/reservation checks.

`game/constructionDrag.ts` holds only scene gesture history (including whether it left its starting tile), endpoints, direction and a memoized read-only proposal. Its cache keys Wood balance, topology, actor reservations (including Pete’s custody mode), unlocks and gesture coordinates; beginning/cancelling/world replacement invalidates it. `finish` clears the gesture before invoking the authoritative commit, so a second pointer-up cannot replay it. `FactoryScene` owns canvas-origin primary-down/release, cursor conversion through the existing camera helper, live arrows/links/crosses/diamonds, blue reused infrastructure, amber reversal circles and explicit snap markers, and one reusable zoom-compensated text object. Preview rendering never commits. Poles reuse existing hover connection/coverage graphics for single placement. A live simulation may invalidate a former preview; release always checks again.

`game/placementRotation.ts` holds an ephemeral anchored tile, preset/live direction and CSS-pixel pointer history for directional single placements (miner, furnace, assembler, inserter, splitter). A 24-pixel radial threshold enables dominant-axis rotation with horizontal ties. The scene reuses its existing arrows/ports and `placementInfo` for anchored previews, and releases through authoritative `placeBuilding` after live validation. R rotates the pending orientation; unchanged pointer coordinates do not undo keyboard rotation. It shares construction cancellation/cleanup and never changes belt/pole/landscape gestures or saved state.
